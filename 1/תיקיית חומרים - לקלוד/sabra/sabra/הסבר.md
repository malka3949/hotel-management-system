# 🌵 צבר (Sabra) — איך זה עובד, רכיב-רכיב

סקייל ל-Claude Code שגורם ל-Claude לדבר ולכתוב קוד כמו מפתח ישראלי דוגרי:
תכל'ס, בלי פלאף, קוד רזה אבל לא רשלני. בהשראת CAVEMAN ו-PONYTAIL.

---

## 1. מה זה בכלל "סקייל" (Skill)?

סקייל = קובץ הוראות ש-Claude Code טוען וקורא, שמשנה את ההתנהגות שלו.
זה לא קוד שרץ — זה **טקסט הנחיות** ש-Claude מקבל. כשהסקייל "פעיל", ההנחיות
שלו חלות על כל תשובה.

הקובץ המרכזי תמיד נקרא `SKILL.md` ומורכב משני חלקים:
- **Frontmatter** (החלק בין `---` בראש) — מטא-דאטה: שם הסקייל, תיאור, ומתי להפעיל.
- **גוף** (כל השאר) — ההנחיות עצמן ל-Claude.

## 3. מה יש בתוך ה-SKILL.md — חלק-חלק

### א. ה-`description` (בראש הקובץ)
זה **מנגנון ההפעלה**. Claude קורא את התיאור ומחליט מתי להפעיל את הסקייל לבד.
התיאור כולל ביטויי-טריגר: "דוגרי", "תכל'ס", "תהיה ישראלי", "be direct" וכו'.
כשמשתמש כותב אחד מהם — צבר נכנס לפעולה אוטומטית.

### ב. Persistence (התמדה)
מגדיר שהסקייל נשאר פעיל **בכל תשובה** עד שמכבים אותו במפורש
("די צבר" / "stop sabra" / "normal mode"). בלי זה, סקייל היה משפיע פעם אחת ונעלם.

### ג. שני הצירים — מה שמייחד את צבר
1. **טון (איך מדבר)** — תכל'ס קודם, בלי hedging, בלי פלאף תאגידי, ביטויים ישראליים טבעיים.
2. **קוד (מה בונה)** — "סולם החלטות": בכלל צריך? → כבר קיים? → ספרייה סטנדרטית? →
   פיצ'ר נייטיב? → שורה אחת? → רק אז קוד מלא. המטרה: הפתרון הכי רזה שעובד.

> CAVEMAN דוחס *מילים*. PONYTAIL דוחס *קוד*. צבר משלב את שניהם + חוצפה ישראלית
> שמאתגרת את השאלה עצמה.

### ד. טבלת עוצמה (lite / full / ultra)
כמו ווליום. בוחרים עם `/sabra lite|full|ultra`:
- **lite** — ישיר אבל מנומס.
- **full** — ברירת מחדל. דוגרי מלא.
- **ultra** — חוצפה מקסימלית, YAGNI קיצוני, מאתגר אותך ישירות.

### ה. חריגי בטיחות
צבר **אף פעם** לא מקצר על חשבון בהירות ב: אזהרות אבטחה, אישור פעולות בלתי הפיכות,
ודיוק טכני. וגם לא עצלן ב: בדיקות קלט, טיפול בשגיאות, אבטחה, נגישות.
"שיטת מצליח חכמה", לא רשלנות.

## 4. ה-badge בשורת הסטטוס (התוספת הוויזואלית)

כשמתקינים עם `install.sh`, מופיע סימון צבעוני בשורה התחתונה של Claude Code:
`🌵 צבר·ultra`. הצבע משתנה לפי העוצמה (תכלת=lite, ירוק=full, אדום=ultra).

**שני ההוקים — הלב של ההפעלה:**

*1. `sabra-prompt.sh` (UserPromptSubmit) — on-demand.*
רץ על כל הודעה שאתה שולח. מזהה טריגר ("צבר"/"sabra"/"/sabra ultra"/"דוגרי"/"be direct"...)
וכותב את העוצמה ל-`~/.claude/sabra.state` — **דטרמיניסטי, בלי תלות במודל**, אז ה-badge
נדלק ברגע שמפעילים. טריגרי כיבוי ("די צבר"/"stop sabra"/"normal mode") מוחקים את הקובץ.

*2. `session-start.sh` (SessionStart) — always-on או ניקוי.*
רץ בתחילת כל סשן חדש, וקורא את `SABRA_AUTOSTART` מ-`~/.claude/sabra.conf`:
- **`0` (on-demand, ברירת מחדל):** מוחק את ה-state — אין badge רפאים מסשן קודם, צבר כבוי
  עד שמפעילים (דרך ההוק הראשון).
- **`1` (always-on):** צבר פעיל מההודעה הראשונה — כותב את ה-state **ומזריק את הוראות
  הסקיל ל-context של הסשן** (דרך `additionalContext`), כך שההתנהגות דולקת בלי שתפעיל כלום.
  עוצמת ברירת המחדל = `SABRA_AUTOSTART_MODE`.

`statusline.sh` קורא את ה-state ומצייר את ה-badge. מה מציגים בשורה (badge / מד קונטקסט /
compact-wide) ומצב ההפעלה (always-on/on-demand + עוצמה) — הכל ב-`~/.claude/sabra.conf`,
ש-`install.sh` כותב לפי מה שבחרת (ואפשר לערוך ידנית בכל רגע).

**למה צריך `install.sh` בשביל ה-badge ולא מספיק להעתיק קובץ?**
מגבלת פלטפורמה: Claude Code **לא** מאפשר לסקייל/פלאגין להגדיר את שורת הסטטוס —
היא חיה רק בהגדרות האישיות של המשתמש (`settings.json`). לכן `install.sh` כותב
את החיווט לשם. זו בדיוק הסיבה ש-CAVEMAN גם משלוח install.sh.

## 5. שתי דרכי התקנה לתלמידים

### דרך א' — רק ההתנהגות (הכי פשוט, קובץ אחד)
```bash
# העתק את SKILL.md לתיקייה הזו (צור אותה אם אין):
mkdir -p ~/.claude/skills/sabra
cp SKILL.md ~/.claude/skills/sabra/SKILL.md
```
פתח סשן חדש של Claude Code → הקלד `/sabra` → עובד.

### דרך ב' — הכל כולל ה-badge
```bash
tar -xzf sabra.tar.gz
cd sabra
bash install.sh
```
דורש `jq` מותקן. פתח סשן חדש → `/sabra ultra` → תראה 🌵 בשורה התחתונה.
