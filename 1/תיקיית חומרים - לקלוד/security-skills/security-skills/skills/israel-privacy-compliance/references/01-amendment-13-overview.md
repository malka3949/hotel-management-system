# תיקון 13 לחוק הגנת הפרטיות — סקירה (Overview)

מסמך-בסיס לסוכן. מסכם את מסגרת הדין הישראלי הרלוונטית לבניית/ביקורת מערכת תוכנה. הסוכן טוען את
זה תחילה כדי להבין את התמונה, ואז את קובץ-העומק של הקטגוריה שלו.

## מה זה ומתי
- **תיקון 13 לחוק הגנת הפרטיות** — נכנס לתוקף **אוגוסט 2025**. מרחיב הגדרות מידע, מחזק זכויות נושא
  המידע, ומוסיף **פיצויים לדוגמה** (אכיפה אזרחית כבדה) + סמכויות אכיפה לרשות.
- **תקנות הגנת הפרטיות (אבטחת מידע), התשע"ז-2017** — הדרישות הטכניות לפי **רמת אבטחה** של המאגר.
- **טיוטת הנחיית הרשות בנושא AI (אפריל 2025)** — דרישות נוספות כשמערכת מעבדת מידע אישי באמצעות AI.

## שלוש שכבות הרגולציה (איך הסוכן חושב)
```text
1. סיווג המידע      → איזה מידע מעובד? (אישי / רגיש מיוחד)        → references 02
2. רמת האבטחה       → לאיזו רמה המאגר משתייך? (בסיסית/בינונית/גבוהה) → references 03
3. דרישות טכניות    → מה חובה ברמה הזו? (גישה/לוגים/הצפנה/זכויות/AI) → references 04-08
```
**הכלל:** סוג המידע + כמות + מספר מורשים → קובעים את רמת האבטחה → קובעת אילו דרישות טכניות חלות.
אי-עמידה = חשיפה לפיצויים לדוגמה (עד 10,000 ₪ לכל נושא-מידע בהפרות מסוימות, ללא הוכחת נזק).

## תוצר התהליך
המערכת **לא** משנה קוד. היא מפיקה **מסמך תאימות מפורט** (עברית) עם:
- סיווג המידע + רמת האבטחה הנדרשת + נימוק.
- ניתוח פערים לכל קטגוריה, עם **ציטוט סעיף/תקנה** + `file:line` בקוד + הסבר הפער.
- **תוכנית פעולה מתועדפת** (High/Medium/Low) עם המלצות ברמת-קוד.
- כל ממצא מעוגן ב**לשון החוק** (הציטוטים נמצאים בקבצי ה-references).

> אזהרה משפטית שהמסמך חייב לשאת: זהו ניתוח תאימות טכני, **לא ייעוץ משפטי**. עמידה מלאה דורשת גם
> תשתיות מאובטחות, תהליכים ארגוניים, וייעוץ משפטי — ולא רק קוד.
